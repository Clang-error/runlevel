        권한 — 왜 root 로 안 주는가
        

            
        문제 터미널은 일반 계정(student)으로 돕니다.
                자유 터미널과 기본명령어의 예시는 root 로 돕니다 
        —
                연습해보는 자리라 권한에 걸려 멈추지 않는 편이 낫다고 봤습니다.
            
        

            
        root 는 권한 검사를 통째로 우회합니다. chmod 000 을 걸어둔 파일도
                그냥 읽히고, 남의 파일도 마음대로 고쳐집니다. 그 상태로 권한을 배우면
                "막힌다"는 감각이 아예 생기지 않습니다. 그래서 문제는 일반 계정으로 둡니다.
            
        

            
        su 와 sudo 는 다릅니다
        

            
        su root 는 관리자가 되는 것이고,
                sudo 는 일반 사용자가 명령 하나에만 관리자 권한을 빌리는 것입니다.
                이름이 비슷해서 같아 보이지만 하는 일이 다릅니다.
            
        

            
        여기서 su root 는 막혀 있습니다. root 계정의 비밀번호를 잠가두었습니다.
                열어두면 그 한 줄로 모든 권한 문제를 건너뛸 수 있어서, 일반 계정으로 푸는 의미가 사라집니다.
        

            
        이건 이 사이트만의 사정이 아닙니다 —
                요즘 배포판도 root 로그인을 잠그고 sudo 로만 올라가게 합니다.
            
        

            
        sudo 도 처음에는 안 됩니다
        

            
        기본 상태에서 sudo 를 치면
                student is not allowed to execute ... 로 거절당합니다.
            
        

            
        권한을 아무에게나 주면 su 를 막은 것도 의미가 없습니다.
                sudo 로 뭐든 된다면 결국 관리자와 같으니까요.
                누가 무엇을 할 수 있는지는 /etc/sudoers 에 적혀 있고, 그걸 다루는 법이 sudo 문제들입니다.
            
        

            
        권한을 받은 뒤에는 비밀번호를 묻지 않습니다.
                실제 서버에서는 대개 물어보는데, 연습에 방해가 되어 꺼두었습니다.
                그 부분만 실제와 다릅니다.
            
        

            
            
        처음부터 root 인 문제도 있습니다
        

            
        mount, mkfs 처럼 관리자만 할 수 있는 일을
                다루는 문제는 root 로 시작합니다.
